# 壁纸时移 · 参考图到导入包

交付真实生成的图片和一个可导入的 `.zip`，不只交付提示词。此技能独立于项目源码，可复制到其他 Agent 的技能目录。需要图像生成/编辑工具、Python 3.10+ 和 Pillow（`python -m pip install Pillow`）。工具不可用时说明缺少的能力，不用占位图冒充成品。

## 先确认生成方案

本流程有三个用户确认点：生成思路、画面要求、成图验收。每个确认点都必须获得用户明确回复后才能进入依赖它的下一步；沉默或仅告知默认值不算确认。用户在本次任务中已经明确指定或确认的内容直接沿用，只问未确定的部分。笼统的「帮我生成并打包」不代表已经验收尚未生成的图片。

先查看用户提供的每张参考图，提取主体、位置、镜头、地平线、画风和材质，然后依次确认：

1. **生成思路**：询问用户希望做「同一场景随时间变化」，还是其他方案，例如同一角色不同场景、按心情切换、每张独立主题。默认推荐同一场景六张：黎明 04:00、早晨跟随日出（04:30–09:30，读不到时 06:00）、正午 11:00、午后 14:00、夜晚跟随日落（15:30–22:00，读不到时 18:00）、深夜 23:00，但须得到认可后才能采用。一起确认张数、各张内容和切换时间；其他方案也需要对应的每日时间表。
2. **画面要求**：结合参考图提出构图建议，询问是否给锁屏时钟留空间、是否需要文字或其他画面元素、是否保留原构图。推荐主体在中下部，上方约四分之一低细节、关键内容不贴边、不额外添加文字或 UI；这些是可调整的建议，不能覆盖用户想保留的参考图文字或设计。一起确认屏幕比例/尺寸和桌面模糊强度；没有设备信息时推荐竖屏 9:19.5、1440×3120、模糊 10。

每次提问尽量简短，给出结合参考图的具体建议和可选方向，不一次抛出长问卷。两个确认点都明确后，简要复述已确认的方案，再开始生成。多张参考图有冲突时，在这里确认其用途和主参考图。

## 按已确认方案生成

使用当前 Agent 可用的图像生成/编辑工具，并遵循该工具自己的调用约定。每次生成都实际传入用户参考图；如果工具支持多图参考，可额外传入已选定的一张生成图来稳定构图。不要只靠文字回忆参考图。参考图无法访问时请用户重新提供；不要假装已经看过。

每个时段生成一张独立、清晰的壁纸，不用拼图代替导入图片。采用「同一场景随时间变化」时，固定视角、主体身份、尺度、建筑/地形位置和画风，只改变时间、光线、天空、阴影、窗灯与合理的环境状态；夜晚图表达太阳已落下、暮色与灯光，不能仍画成太阳尚在地平线上的夕阳图；深夜图比夜晚更暗、更安静，夜景仍需能辨认主体。采用其他方案时，按用户确认的变化维度生成，不强制锁定场景或只改光照。构图、文字、时钟留白都服从已确认的画面要求。

提示词可采用这种骨架，再补上实际观察到的细节；不要把尚未确认的默认假设写进提示词：

> 以附图为视觉参考，按已确认的「{生成思路}」制作「{图片名/时段}」手机壁纸。保持 {用户要求固定的元素}，变化 {本张的内容与光照等要求}。单张完整画面，目标比例 {比例}，构图与留白 {已确认要求}，文字及其他元素 {已确认要求}。

工具不支持目标尺寸时，先生成最接近目标比例的图，确保主体位于最终安全裁剪范围内；打包脚本会居中裁剪、缩放并报告裁剪和放大。明显不合比例时优先重新生成或用图像工具扩图，不能靠拉伸凑尺寸。

默认六张方案获得认可时，同时采用日出、日落 anchor；`start` 是回退时间，不代表当天实际切换时间。APP 将有效日出限制在 04:30–09:30、有效日落限制在 15:30–22:00，早于下限按下限、晚于上限按上限，缺失时使用 `start`。这保证默认六张的顺序；自定义其他固定节点时仍需检查与安全范围是否冲突。展示时间表时说明跟随范围和回退值，不把回退值标成实际日出日落。

查看所有实际输出，按已确认方案检查一致性、各张差异、文字准确性、画面瑕疵和裁剪安全；有问题就有针对性地重做。保留未经模糊的原图：APP 自动制作桌面模糊图，每个时段只需一张源图。

## 展示成图，等待验收

在创建 ZIP 之前，展示整套实际生成图片，并标注每张的编号、名称和开始时间。可以用联系表辅助对比，但用户须能查看每张完整图片或打开原图，不能只给提示词、文件名或文字描述。无法展示时提供可访问的图片链接，并等用户查看反馈。

预览应反映最终尺寸下的画面。若打包会裁剪、缩放或铺白底，先调用 `scripts/package_set.py` 的 `render(source, size)` 得到 JPEG 字节并保存为预览，暂不调用 `build`，让用户看到实际处理效果。计划仍引用原始生成图，以相同尺寸打包，避免重复压缩。说明发生的裁剪/放大，不把插值当作原生分辨率。

这是第三个确认点：明确询问「这套图和时间安排是否满意，可以打包了吗？哪些图需要调整？」收到明确验收与打包许可后才执行下一节。用户要求修改时，只重做受影响的图片，更新整套预览并再次等待确认。用户调整生成方向或画面要求时，同步更新对应的已确认方案；不把修改意见当作打包许可。

## 制作和验证导入包

仅在成图和时间表通过用户验收后开始。阅读 [references/package-format.md](references/package-format.md)，尤其是大小限制和 `anchor` 语义。在工作目录保存已确认的图片和 `plan.json`。计划中的 `file` 相对计划文件所在目录，例：

```json
{
  "name": "海边的一天",
  "blur": 10,
  "items": [
    {"file": "generated/dawn.png", "start": "04:00", "label": "黎明"},
    {"file": "generated/morning.png", "start": "06:00", "label": "早晨", "anchor": "light-start"},
    {"file": "generated/noon.png", "start": "11:00", "label": "正午"},
    {"file": "generated/afternoon.png", "start": "14:00", "label": "午后"},
    {"file": "generated/night.png", "start": "18:00", "label": "夜晚", "anchor": "dark-start"},
    {"file": "generated/deepnight.png", "start": "23:00", "label": "深夜"}
  ]
}
```

执行技能目录下的脚本（将 `<skill-dir>` 替换为本技能实际路径）：

```bash
python <skill-dir>/scripts/package_set.py build --plan /absolute/work/plan.json --output /absolute/work/海边的一天.zip
python <skill-dir>/scripts/package_set.py check /absolute/work/海边的一天.zip
```

`build` 处理 EXIF 方向，将透明部分铺为白底，统一为 RGB JPEG（质量 95），去掉源图元数据，在 ZIP 根目录写入真实导入清单并自动校验。用 `--size 1080x2340` 等覆盖默认尺寸。脚本拒绝覆盖已有输出，换名保存。检查器专门验证本技能产物，比 APP 接收任意第三方包的规则更严格。

查看 ZIP 内最终处理后的图片，确保与用户验收的预览一致；程序校验不能代替视觉检查。若尺寸或处理参数改变了画面，先重新展示受影响的预览供用户确认，再重打包。交付 ZIP 的可下载链接和简短时间表，可附预览；不要把计划文件或技能安装包误当作壁纸包。

告诉用户：把 ZIP 保存到手机 → 壁纸时移首页「导入」→ 选择 ZIP → 检查时间表并启用。导入后默认不启用，也可从文件管理器以「壁纸时移」打开 ZIP。不要声称已在真机导入，除非实际验证过。
